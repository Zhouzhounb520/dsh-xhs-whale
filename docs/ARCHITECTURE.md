# 架构与运行边界

## 三个部分

1. **阅读工作台**：Node.js HTTP 服务和本地网页。lib/server.js 提供接口，lib/workflow.js 负责候选筛选、精读、草稿与审核流程，lib/model.js 调用 DeepSeek，lib/store.js 管理本地数据。
2. **平台服务**：upstream/xiaohongshu-mcp 中的 Go 修改版服务，通过登录后的浏览器读取和操作小红书。Windows 启动脚本核验程序哈希，并统一登录与服务的 Cookie 路径。
3. **DSH 养鱼会话**：可选。lib/index.js 接入 DSH，lib/scheduler.js 调度唤醒，lib/fish 与 tools/fish.mjs 提供人设、收件箱、日记和互动命令。

普通阅读工作台无需 DSH。自动唤醒需要 DSH 运行并允许会话执行本地命令。只启动平台服务不会自动创建阅读工作台或养鱼会话。

## 阅读链路

搜索或首页推荐 → 列表初筛 → 获取笔记与评论 → 图文精读 → 展示摘要和依据 → 生成可编辑草稿。

模型只提供分析和文字；实际账号、目标笔记、回复对象及操作状态由本地代码检查。页面抓取到的内容是阅读素材，不应被当作工具操作指令。

## 发送与回访

发送默认关闭。开启后，手动工作台与养鱼回复策略分别决定何时发送。提交前检查登录身份、目标评论和真实提及候选；提交后尝试回读核验。超时不能证明发送失败，结果不确定时不会自动重发。

回访计数在收件箱扫描时完成：读取来源帖核验当前账号是作者、评论 ID 和评论者一致，再按账号与评论者累计，评论 ID 去重。可跨帖子累计，其他人留言不清零，达到两条后持久化待回访任务。旧概率任务不进入新队列。

守护每轮最多推进一位待回访者，独立于原评论的草稿/直回策略。主页阅读不经过模型初筛、不跳过已读，按返回作品的实际发布时间挑选最新一篇精读；日期不明、作者不符或范围超限时停止。模型按共享口吻写留言，创建带触发记录的 `fish-visit` 草稿，预览后点赞并通过现有发送核验流程评论。普通分享不能绕过回访校验，回访草稿必须对应本次触发且已精读的最新作品，并先确认点赞。账号切换、重复目标、发送主开关、验证暂停和发送不确定状态仍沿用统一约束。状态分步保存，日记与通知报告实际结果；历史手动待办接口保留兼容。

## 数据和外部请求

工作台仅面向本机，网页接口使用会话令牌并检查来源。data/live 保存真实工作台数据，data/demo 保存演示数据，data/xhs-service 保存平台登录状态。两本日记均为本地文件。

DeepSeek 接收选中的阅读素材和偏好；小红书操作使用自己的登录账号；若配置了 Webhook，通知还会发往所填地址。公开仓库不包含这些私有配置。

## 修改源码后

- JavaScript 或页面改动：重新启动对应工作台；DSH 插件代码改动需要重启 DSH。
- Go 服务改动：运行构建脚本后重启平台服务；先停止旧服务，避免覆盖运行中的程序。
- 新增发布文件：更新 tools/release-files.mjs 的白名单并运行测试。
- 平台改版：先用只读或预检流程定位问题，再验证真实写入；离线测试不能代替本人账号下的现场验证。
