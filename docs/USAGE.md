# 使用与排障

## 阅读和回复

1. 在“发现与阅读”设置关键词、兴趣和排除词，开始筛选。
2. 打开结果，对照正文、图片和模型阅读依据。
3. 为帖子或指定评论生成草稿，编辑后审核。
4. 开启发送主开关后，才可按页面流程发送；养鱼会话按其单独配置的回复策略工作。
5. 结果为“需核对”时，先在平台确认是否已发出，再处理本地状态，不要直接重发。

命令行入口为 node tools/fish.mjs；不加参数可查看帮助。常用命令包括 status、selftest、inbox。由 DSH 生成的 fish/fish.cmd 带本机路径，不应分享。

## 聊天口吻与表达学习

小鲸鱼按情境使用普通口语和鲸鱼特色表达。刚明白时可以说“哦哦”，认同时可以说“确实哦”，被夸时可以只回“嘿嘿”；也可以直接接内容。短回复不必补总结、问题或鲸鱼动作，顶层评论仍需回应具体内容。语气词和鲸鱼词都没有使用配额。

口吻规则集中在 `lib/fish/voice.js`，自动唤醒、收件箱回复与手动草稿共用。默认人设文件 `fish/AGENTS.md` 由 `lib/fish/agents.js` 引用同一份口吻生成。修改源码后重新启动工作台或重新加载 DSH 插件，后续唤醒和新草稿会使用新规则；其他安装目录中已存在的自定义 `fish/AGENTS.md` 不会被程序覆盖，如有强制每条玩梗的旧规则，需要同步调整。

表达学习借鉴 [MaiBot 的人设与表达学习设计](https://docs.mai-mai.org/manual/configuration/bot-config)，通过现有私人日记记录“情境表达”：来源、意图、短表达、适用范围、改写和真实反馈。下次回复前按情境参考，主人明确说刻意的表达停用或改写；没有新发现不强制记录，不从机器人自己的旧回复循环学习。这是提示词驱动的日记学习，未接入 MaiBot 服务、向量检索或训练模型。

## 回访与真实 @

同一人在小鲸鱼自己的帖子下累计至少两条不同留言后，确定触发回访。可跨帖子累计，其他人的留言不清零；只计算核验过帖子作者和评论者的留言，不计别人帖子里的 @、自己的回复或重复通知。累计记录会持久保存，不要求先自动回复原评论，原评论只写草稿也可以触发回访。旧版的概率和 72 小时间隔不再生效。

收件箱守护在配置的监听时段内每轮最多处理一位待回访者：核对对方主页本次返回的作品（最多 30 篇）的发布时间，避开置顶旧帖，只精读最新一篇，再写自然具体的留言，预览核验后先点赞、后发送评论。最新作品已读也不会换成旧帖；该作品已留过言、已有待处理或发送不确定记录时直接跳过，不改发到更旧作品。当前主页接口只返回本次加载到的作品，无法保证覆盖未加载的页面；缺少有效日期或超出核验范围时停止，不猜最新作品。

需要开启回访、监听、发送主开关和点赞开关；点赞额度仍适用。发送或点赞开关关着时任务保留待处理。每次回访的真实结果写入日记和工作台通知；`node tools/fish.mjs visit --tasks` 查看记录，`visit` 列待回访，`visit --comment <触发评论ID>` 可推进一项待回访并自动点赞、留言。遇到验证、账号/作者不符、预览失败或点赞失败时停止；评论结果不确定时不会自动重发。再次出现新留言可安排检查主页，但同一作品不重复评论。

普通分享中的真实 @ 由修改版服务在浏览器里选择用户候选。请先设置主人身份，并在分享设置中打开对应开关。没有匹配到候选时应处理提示，不用普通文本假冒真实 @。自动回访不 @ 主人；旧的 `visit --prepare` 仅兼容历史手动待办，不参与自动流程。

## 登录窗口自动关闭

登录 EXE 是一次性登录工具，保存登录状态后退出属正常行为。后台服务是另一进程。使用启动脚本的 -Login 参数可以确保两者使用同一份 Cookie。

直接运行登录工具产生了根目录 cookies.json 时，可导入：

```powershell
.\scripts\启动小红书服务.ps1 -ImportCookies .\cookies.json -Restart
```

## 搜索超时或验证

平台验证页可能使搜索等待超时。工作台识别验证问题后暂停；按界面提示打开验证窗口，本人完成后再继续。不要通过增加重试频率处理验证。

## 缺少修改版服务

安装脚本现在会自动构建。若此前用了 -SkipBuild，或只有官方 EXE，请运行：

```powershell
.\scripts\构建评论修复版.ps1
```

Go 不在 PATH 时使用 -GoExe 指定；依赖下载失败时检查网络，或用 -GoProxy 指定自己信任的 Go 模块代理。普通运行默认使用修改版；-Original 仅作诊断，不保证完整的评论核验和提及功能。

## 端口与启动

工作台默认 18061，演示 18062，平台服务 18060。启动脚本只管理已核实路径和哈希的本项目进程；端口被别的程序占用时不会强行结束它。

工作台可通过 node tools/xhs.mjs serve --port 18063 使用另一端口；DSH 的默认入口仍是 18061。同一数据目录仅允许一个工作台实例。

## 浏览器兼容问题

若 Windows 报 side-by-side configuration is incorrect，可尝试 scripts/准备兼容浏览器.ps1，再以 -UseCompatBrowser -Restart 启动服务。该功能依赖本机已安装且签名有效的 Google Chrome，属于可选兼容路径；不加 -UseCompatBrowser 重启可恢复默认。

## 模型连接

区分密钥错误、余额错误、模型不可用和网络超时。进程遇到 EACCES/EPERM 时应检查其运行环境的联网权限。不要在公开 Issue 中提供 API Key、Cookie 或未经脱敏的请求头。
